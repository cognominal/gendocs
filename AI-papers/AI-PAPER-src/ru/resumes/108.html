Поставленный вопрос

В начале 2024 года агент на основе LLM действует чаще всего, выдавая вызов инструмента в формате JSON или текст в фиксированном формате: одно действие за ход, с типизированными аргументами. Синъяо Ван, Хэн Цзи и соавторы (Университет Иллинойса в Урбане-Шампейне и Apple) предлагают, чтобы действием был исполняемый код на Python. В коде есть переменные, циклы и условия; он сочетает несколько инструментов за один ход и использует все существующие библиотеки. Сообщения об ошибках интерпретатора служат обратной связью для самоисправления.

Устройство

  • CodeAct: на каждом ходу модель пишет блок кода. Интерпретатор Python исполняет его и возвращает вывод или ошибку как наблюдение, по схеме мысль—действие—наблюдение из ReAct (статья 56).
  • M3ToolEval: набор задач, требующих сочетать несколько инструментов на нескольких ходах, чтобы сравнить CodeAct с JSON и текстом при равных действиях.
  • CodeActInstruct: 7 000 многоходовых взаимодействий, собранных с CodeAct, на которых дообучены Llama 2 и Mistral; так получен CodeActAgent.

Результаты

  • На 17 LLM CodeAct не уступает JSON и тексту или превосходит их: до 20 пунктов успеха больше и до 30 % действий меньше.
  • Разрыв больше всего у самых сильных моделей: они умеют пользоваться управлением потоком и библиотеками.
  • CodeActAgent умеет обучить модель с помощью scikit-learn или построить графики и исправляет себя по трассировкам ошибок. Его общие способности после дообучения не снижаются.

Наследие

CodeAct стал агентом по умолчанию в OpenHands (статья 112) того же первого автора. Идея распространилась по всей экосистеме. Обвязки для кода дают модели shell и позволяют ей писать собственные скрипты, вместо того чтобы умножать специализированные инструменты: у Pi всего четыре инструмента, включая bash. «Code mode» клиентов MCP поступает так же: модель пишет код, вызывающий инструменты, вместо отдельного JSON-вызова для каждого.
